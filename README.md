# 核心网操作响应预测数据集

本说明对应 CausalMoETCN 当前使用的核心网 1 秒版本数据归档 `hexinwang_crn_causal_1s.npz`。变量记号沿用论文：A 表示操作干预及其作用对象，X 表示网络协变量，Y 表示 KPI。历史 KPI 与历史协变量分别说明。

## 数据概况

数据来自一个基于 Kubernetes 的通信网络实验平台，包含 4 个 gNB 和 40 个 UE，Gold、Silver 两个业务组各配置 20 个 UE。在固定拓扑和中等业务负载下，平台按计划执行核心网与接入网联合操作，同时记录接口流量、会话状态、业务表现和宿主机资源使用情况。数据围绕一个具体任务组织：给定操作前的网络状态与已知未来操作计划，预测 N3 上行、N3 下行和 N6 业务侧聚合比特率的后续变化。

当前数据集由 D01—D07 共 7 个独立采集批次组成。每个批次对应一次完整实验运行，持续约 24 小时 16 分钟；一个批次内的时间序列保持连续，样本窗口在该批次内部构造。D 编号同时标识实验批次和预先确定的数据划分，实际采集先后顺序另由时间戳记录。采集范围覆盖 2026 年 8 月 3—13 日（UTC）。

原始主表按 1 秒时间桶组织，共 611,777 行、81 列。建模从中选取 18 个协变量和 3 个目标 KPI，并将操作计划编码为 11 维多热向量。部分字段来自状态快照或业务流、抓包代理观测，其原生更新频率和统计口径见字段字典。

| 项目 | 当前版本 |
| --- | --- |
| 采集边界 | 7 个独立实验运行批次，D01—D07 |
| 主要关注对象 | 核心网 N3、N6 接口的 KPI 响应及相关网络状态 |
| 平台配置 | 4 个 gNB、40 个 UE；Gold 与 Silver 各 20 个 UE；中等业务负载 |
| 时间组织 | 1 秒时间桶；保留各批次自身的时间轴 |
| 原始数据规模 | 611,777 行 × 81 列 |
| 操作条件 A | 11 维：6 类核心网操作、3 类接入网操作、2 个业务组标志 |
| 原始协变量 X | 18 个；加入逐变量观测掩码和观测间隔后形成 54 个通道 |
| 目标 KPI Y | 3 个：N3 上行、N3 下行、N6 聚合比特率 |
| 历史长度 L | 300 步，对应 300 秒 |
| 预测长度 P | 100、200 或 300 步，对应 100、200 或 300 秒 |

## 批次划分与样本组织

数据按完整采集批次划分训练、验证和测试集。操作事件窗口与其匹配对照来自同一批次，因此保留在同一数据划分中。

| 批次 | 用途 | 原始行数 | 保留的操作事件窗口 | 匹配对照窗口 | 样本合计 |
| --- | --- | ---: | ---: | ---: | ---: |
| D01 | 训练 | 87,435 | 72 | 72 | 144 |
| D02 | 训练 | 87,327 | 72 | 72 | 144 |
| D03 | 训练 | 87,400 | 72 | 72 | 144 |
| D04 | 训练 | 87,408 | 72 | 72 | 144 |
| D05 | 验证 | 87,403 | 72 | 72 | 144 |
| D06 | 测试 | 87,413 | 72 | 72 | 144 |
| D07 | 测试 | 87,391 | 71 | 71 | 142 |
| 合计 | — | 611,777 | 503 | 503 | 1,006 |

原始采集包含 504 组联合操作，每组由一个核心网操作、一个接入网操作及其业务组组成，共覆盖 12 种预设组合。计划持续时间为 120 或 180 秒。样本选择保留了 503 组事件；D07 的一个事件因原先 5 秒版本中的目标时间桶缺少真实观测而被排除。当前 1 秒版本沿用已冻结的事件、对照、时间锚点和数据划分。

每个事件匹配一个同批次的对照窗口。对照候选的完整 600 秒窗口内没有计划操作，匹配过程使用预测起点之前的 KPI、协变量统计和时刻信息。这些窗口提供历史状态相近、后续计划不同的观测性比较样本。

当前归档为每个样本保存 300 秒历史和 300 秒未来段。P=100、200、300 的任务分别使用相应长度的未来段。样本围绕事件和匹配对照的时间锚点构造，样本数量由事件筛选与匹配结果确定。

## 变量说明

### 操作条件 A

A 记录操作内容及其作用业务组。历史操作与已知未来操作计划采用相同的编码顺序。下表给出预处理归一化之前的二值编码名称，1 表示对应计划条件在该时刻激活，0 表示未激活。

| 编码名称 | 中文含义 | 类型 | 取值 |
| --- | --- | --- | --- |
| `core_n3_block` | N3 接口阻断 | A：核心网操作 | 0 / 1 |
| `core_n3_delay` | N3 接口时延注入 | A：核心网操作 | 0 / 1 |
| `core_n3_loss` | N3 接口丢包注入 | A：核心网操作 | 0 / 1 |
| `core_n4_block` | N4 接口阻断 | A：核心网操作 | 0 / 1 |
| `core_n6_block` | N6 接口阻断 | A：核心网操作 | 0 / 1 |
| `core_upf_stop` | UPF 停止 | A：核心网操作 | 0 / 1 |
| `ran_gnb_restart` | gNB 重启 | A：接入网操作 | 0 / 1 |
| `ran_ue_recreate` | UE 重建 | A：接入网操作 | 0 / 1 |
| `ran_ue_scale_down` | UE 规模缩减 | A：接入网操作 | 0 / 1 |
| `tier_gold` | 操作作用于 Gold 业务组 | A：作用对象 | 0 / 1 |
| `tier_silver` | 操作作用于 Silver 业务组 | A：作用对象 | 0 / 1 |

例如，N3 时延注入与 UE 重建共同作用于 Silver 业务组时，`core_n3_delay`、`ran_ue_recreate` 和 `tier_silver` 同时取 1，其余位置取 0。这样，11 维编码同时表达操作内容和作用对象。计划时间窗定义操作条件的起止，实际 KPI 的变化与恢复过程由观测序列记录。

### 网络协变量 X

18 个原始协变量涵盖控制面会话、注册状态、业务表现、RAN 状态及宿主机资源。下表列出实际字段名、含义与原始单位。

| 字段名称 | 中文含义 | 类型 | 单位或取值范围 |
| --- | --- | --- | --- |
| `cp_pdu_session_success_rate` | PDU 会话建立成功率 | X | %，0—100 |
| `cp_pdu_session_failure_count` | PDU 会话建立失败计数 | X | 次数 |
| `end_to_end_rtt_ms` | 端到端往返时延代理值 | X | ms |
| `jitter_ms` | 时延抖动代理值 | X | ms |
| `packet_loss_rate` | 丢包率代理值 | X | 比例，0—1 |
| `business_completion_rate` | 业务完成率 | X | 比例，0—1 |
| `cp_active_session_count` | 活跃 PDU 会话数 | X | 个 |
| `cp_pending_session_count` | 待完成 PDU 会话数 | X | 个 |
| `cp_pdu_session_request_count` | PDU 会话请求计数 | X | 次数 |
| `registration_success_rate` | UE 注册成功率 | X | %，0—100 |
| `registration_request_count` | UE 注册请求计数 | X | 次数 |
| `ran_pdu_active_count` | RAN 侧活跃 PDU 数量快照 | X | 个 |
| `ready_gnb_count` | 就绪 gNB 数量快照 | X | 个 |
| `observed_ue_count` | 观测 UE 数量快照 | X | 个 |
| `n4_bitrate_bps` | N4 接口比特率 | X | bit/s |
| `host_cpu_pct` | 核心网宿主机 CPU 使用率 | X | % |
| `host_mem_used_pct` | 核心网宿主机内存使用率 | X | % |
| `host_loadavg_1` | 核心网宿主机 1 分钟平均负载 | X | 无量纲 |

RTT、抖动和丢包率来自业务流或抓包代理观测。业务完成率采用最近 60 秒内业务流终态统计的 Gold/Silver 加权聚合值。RAN 侧三个数量字段属于状态快照。上述口径有助于解释操作后的变化速度，也决定了缺失和观测间隔需要单独保留。

### 目标 KPI Y

| 字段名称 | 英文名称 | 中文含义 | 类型 | 原始单位 |
| --- | --- | --- | --- | --- |
| `n3_uplink_bitrate_bps` | N3 Uplink Bitrate | N3 上行比特率 | Y | bit/s |
| `n3_downlink_bitrate_bps` | N3 Downlink Bitrate | N3 下行比特率 | Y | bit/s |
| `n6_bitrate_bps` | N6 Aggregate Bitrate | N6 业务侧聚合比特率 | Y | bit/s |

这三个 KPI 的历史值作为 Y_hist 参与状态编码，未来值作为 Y_fut 提供预测监督。模型同时接收 X_hist、A_hist 和已知的 A_fut；未来真实 KPI 保留在标签侧。预测第 j 步时，操作信息使用到该步为止。

## 预处理与输入维度

协变量缺失位置沿时间方向用最近可用值填充；首次有效观测之前的缺失位置使用训练批次估计的中位数。每个协变量同时附带一个观测掩码和一个距上次有效观测的时间间隔特征，时间间隔采用 `log1p` 变换。因此，X 的输入表示包含 18 个观测值、18 个掩码和 18 个时间间隔，共 54 个通道。

历史 KPI 同样沿时间方向填充，初始缺失位置采用训练批次的目标中位数；归档另存历史 KPI 的原始观测掩码。未来 KPI 的缺失位置保留为 NaN，训练和评估通过目标观测掩码选择有效位置。

当前 `history` 数组按通道存储 A_hist、X_hist 的扩展表示和 Y_hist，共计：

```text
11 个操作条件 + 18 个协变量值 + 18 个观测掩码
             + 18 个观测间隔 + 3 个历史 KPI = 68 个通道
```

其中，A、X、Y 保持各自的变量含义；68 表示历史输入的存储宽度。`history_target_observed_mask` 作为独立辅助数组保存。

KPI 采用相对基线的对数变换。每个样本的基线取预测起点前 60 秒真实观测的中位数：

```text
delta = log1p(KPI_bps) - log1p(baseline_bps)
KPI_bps = expm1(delta + log1p(baseline_bps))
```

运行时的标准化统计量由训练集估计，并在验证、测试阶段固定。归档保留原始 bit/s 值、基线和观测掩码，便于复核指标及反变换。

| 数组 | 形状 | 内容 |

归档还保存事件标识、匹配关系、时间锚点和字段名称。`values` 数组汇集历史与未来段用于归档；模型输入按上表的 `history` 与 `future_treatment` 分别读取，预测段的其他观测留作标签和核查资料。

## 版本与依据

本文档整理于 2026-10-13，描述当前内部实验数据。纳入的数据为 7 个通过最终采集审计的批次：D02、D04 各有一次被后续采集替换的早期诊断运行，另有 6 个批次经历离线报告检查修复，原始采集数据保留不变。结果对应固定拓扑、中等负载与预设联合操作的实验范围，分析时需考虑通过质量筛选后保留批次的选择效应。数据发布状态沿用内部归档记录。

统计、字段含义与预处理依据以下现有资料核对：

- `一周数据集v3.1.md`：采集配置、批次边界、原始规模与操作组合。
- `w1-v3-internal-base-v1/dataset/manifest.json`：原始文件及数据划分。
- `w1-v3-internal-base-v1/documentation/V3_FIELD_DICTIONARY.csv`：字段定义、单位与观测口径。
- `dataset_report_causal_5s.md`：冻结的事件、匹配对照与样本筛选记录。
- `hexinwang_crn_causal_1s.audit.json`、`build_hexinwang_causal_1s.py`：当前 1 秒版本的数组、缺失处理与通道布局。
